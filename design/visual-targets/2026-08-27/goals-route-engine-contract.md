# Goals route engine owner contract

Locked from the owner's 2026-08-27 rejection of the spectacle-only slice:

> the actual logistics of the page don't make sense. it doesnt account for a first action based on what you're actually aiming to achieve. no actual plan of how you'll achieve it etc, none of that psychology stuff i was promised. im a bit disappointed. the UI looks better (the text on the button should be improved) but it isn't backing anything up. there isn't any impressive piece of software behind all the spectacle

The next slice must earn the room with observable software behavior:

- It must learn the desired real-world outcome, current reality, visible proof of success, normal available time, likely snag, and optional horizon before claiming to know the first move.
- It must draft an editable route whose structure changes for finishing something, building a skill, establishing a rhythm, or resetting a situation.
- It must name one current marker, explain why that marker comes next, and create an exact linked Quest from marker identity, plan revision, and attempt number.
- A stale, duplicated, unrelated, or out-of-order Quest must not advance the plan.
- The person must be able to say the plan is too big, unclear, mistimed, low-energy, or aimed at the wrong result; the route must change without erasing honest earlier proof.
- A temporary hard-day rescue must not permanently dilute a repeated marker.
- Ongoing rhythms must open another evidence cycle instead of reaching a dead end.
- Existing goals must be able to gain a route without losing progress already earned.
- The returning room must show position, reason, exact action, specific verb-led CTA, fallback, and route-adjustment affordance without reverting to a dashboard.

This contract replaces the earlier threshold-room slice as the product definition of done. The selected room composition remains a visual source, but it is no longer sufficient evidence by itself.
