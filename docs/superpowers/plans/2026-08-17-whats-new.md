# Room of Days What's New Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show one calm, replayable What's New screen after every Room of Days build released to users, beginning with `1.0.1+13`.

**Architecture:** Keep immutable release copy in a checked-in catalog, device-local seen state behind a small preference gate, and presentation in one reusable screen. `AppShell` claims an unseen release before display and sequences it after onboarding/room links but before Morning Flow; Me opens the same catalog manually.

**Tech Stack:** Flutter/Dart, shared_preferences, flutter_test, existing Room of Days glass/gold/facet primitives.

## Global Constraints

- Automatic display occurs once per shipped `version+build`; unshipped build attempts do not count.
- Fresh installs skip the screen and mark the current release seen.
- Seen state stays device-local and never enters `GameState`, save exports, or cloud sync.
- Mark seen before display; preference failure skips the automatic screen.
- Onboarding and room links precede What's New; What's New precedes Morning Flow.
- Both close and `KEEP GOING` dismiss immediately, with no forced scroll or tour.
- Use one luminous honey-gold action, readable scalable text, and the approved dark warm material system.
- Honor both in-app and operating-system Reduce Motion.
- Preserve all unrelated dirty-worktree changes in `shell.dart`, `me.dart`, `pubspec.yaml`, and release files.

## File Structure

- Create `lib/content/release_notes.dart`: immutable release/highlight records and newest-first catalog.
- Create `lib/release_notes_preferences.dart`: injectable seen-ID store and claim policy.
- Create `lib/screens/whats_new.dart`: automatic/manual full-screen presentation.
- Modify `lib/screens/shell.dart`: launch eligibility, ordered overlay, dismissal handoff, modal semantics.
- Modify `lib/screens/me.dart`: permanent `WHAT'S NEW` entry.
- Create `test/release_notes_test.dart`: catalog/release-file agreement and preference policy.
- Create `test/whats_new_screen_test.dart`: content, dismissal, accessibility, and responsive rendering.
- Modify `test/morning_auto_open_test.dart`: shell launch ordering and once-only behavior.
- Modify `test/my_space_ui_test.dart`: manual entry coverage.
- Modify `RELEASE-CHECKLIST.md`: require a matching release record and upgrade/fresh-install check.

- [ ] **Step 4: Add the injectable preference gate**

```dart
const whatsNewSeenReleasePreferenceKey =
    'room_of_days_whats_new_seen_release_v1';

abstract interface class ReleaseSeenStore {
  Future<String?> read();
  Future<bool> write(String releaseId);
}

class ReleaseNotesGate {
  const ReleaseNotesGate(this.store);
  final ReleaseSeenStore store;

  Future<bool> claim({required String releaseId, required bool freshInstall}) async {
    if (releaseId.isEmpty) return false;
    try {
      if (await store.read() == releaseId) return false;
      if (!await store.write(releaseId)) return false;
      return !freshInstall;
    } catch (_) {
      return false;
    }
  }
}
```

`SharedPreferencesReleaseSeenStore` reads and writes only
`whatsNewSeenReleasePreferenceKey`; it catches no errors itself so
`ReleaseNotesGate` owns the single fail-closed policy.
