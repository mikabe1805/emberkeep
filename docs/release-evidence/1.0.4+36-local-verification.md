  and create the first Quest only after explicit acceptance. Recovery can make
  a difficult day smaller without mutating a route behind the person's back,

  Scrolling, pointer cancellation, and inactive controls stay quiet.

  Goals, Workshop, Recovery, Plans, My Space, Change Space, Journal, and

## Known dependency maintenance item

`npm audit --omit=dev` reports nine moderate entries, all fanning out from one
transitive `uuid <11.1.1` advisory under the current Google/Firebase server SDK
tree. The affected API requires a caller-provided output buffer in UUID v3, v5,
or v6. Room of Days does not import `uuid` or expose those buffer arguments, and
this candidate makes no Functions dependency or deployment change. npm's only
automatic proposal is a forced breaking downgrade of Firebase Admin, so the
candidate leaves the tested production tree intact and records the upstream
upgrade as maintenance work. This is not represented as a clean dependency
audit.

## Immutable receipt protocol

1. Commit every Build 36 source, test, listing, documentation, and screenshot
   change while the candidate manifest remains an unfilled template.
2. Record that candidate commit as the manifest's `sourceRevision`, add the
   lowercase SHA-256 of each of the ten screenshots, and create a second commit
   changing only `store-assets/screenshots/app-store/CANDIDATE-MANIFEST.json`.
3. On the clean receipt commit, the iOS packet verifier must prove that the
   manifest names `1.0.4+36`, its source revision is the immediate parent,
   `HEAD^..HEAD` contains only the manifest, and every screenshot name,
   dimension, opacity, and hash matches.
4. The exact tag `room-of-days-1.0.4-build-36-candidate-4` must point to that
   receipt commit. No branch push or similarly named tag may trigger the iOS
   workflow.

## First Codemagic attempt — no artifact produced

Tag `room-of-days-1.0.4-build-36-candidate` triggered Codemagic build
`6a93b06dad20be13e3fcaf0f` from receipt `e74df23`. Source fetch, SDK setup, and
Flutter packages passed. The combined analyze/test/receipt step failed after 1
minute 34 seconds, and Codemagic skipped code signing, IPA creation, signed-IPA
verification, and App Store Connect publishing. Apple therefore received no
Build 36 binary from this attempt.

The receipt still passes locally after `flutter pub get`, and `HEAD^` resolves
correctly, ruling out the manifest protocol and Windows-generated files. That
Windows pass could not prove macOS package generation. The only new direct
exact-golden suites since the last successful macOS build were the four
Goal-journal opening frames and three Quest-mastery frames; all seven were
Windows-authored but unguarded. The repaired candidate applies the existing
canonical-renderer policy to those comparisons and unshallows the Codemagic
clone so the manifest's parent identity is explicit. The second workflow is
also split into named validation steps, making any residual failure directly
observable in GitHub's build summary.

## Second Codemagic attempt — app gates passed, no artifact produced

Tag `room-of-days-1.0.4-build-36-candidate-2` triggered Codemagic build
`6a93b48fad20be13e3fcb4a3` from receipt `80fe19f`. Analyze passed in 14 seconds,
the complete 945-test app regression suite passed in 1 minute 19 seconds, and
the feature-on friends/discovery packet passed in 11 seconds. Only the
five-second iOS submission-packet step failed. Codemagic again skipped code
signing, IPA creation, signed-IPA verification, publishing, and Apple upload.

The same receipt is clean and passes locally, its manifest source revision is
its immediate parent, and the receipt commit changes only the manifest. The
remaining environment difference is the tag checkout: Codemagic documents a
one-commit default for tag builds, while the receipt deliberately requires
`HEAD^`. Candidate 3 requests depth two and also performs a bounded depth-two
fetch if the parent is still absent. It names receipt identity and packet
verification separately, runs the packet check before any tests, and confirms
afterward that validation left tracked sources unchanged. This preserves the
two-commit receipt contract instead of weakening it.

## Third Codemagic attempt — receipt history passed, no artifact produced

Tag `room-of-days-1.0.4-build-36-candidate-3` triggered Codemagic build
`6a93b780ad20be13e3fcb889` from receipt `2fe6b7b`. The new bounded history step
passed, proving the tag checkout had the immediate parent required by the
manifest. Flutter package resolution then passed, but the packet verifier
stopped on its clean-checkout requirement. Analyze, tests, code signing, IPA
creation, signed-IPA verification, and Apple upload did not run.

The pinned Flutter 3.44.2 source explains the platform difference. On macOS,
Xcode 26.4 makes Swift Package Manager available; because the current plugin set
also contains CocoaPods fallbacks, `flutter pub get` calls CocoaPods setup. With
no checked-in `ios/Podfile`, that setup creates Flutter's standard Podfile and
adds Pods support includes to the tracked Debug and Release Xcode configs.
Windows has no Xcode, so the same command cannot take that branch and the local
receipt remains clean. Candidate 4 checks in those deterministic iOS inputs at
the app's existing iOS 15 floor and adds a named post-package cleanliness gate.
The final full packet verifier remains unchanged and still runs both before and
after the macOS validation suites.

## Physical TestFlight acceptance still required

After Apple processes Build 36, install it over the current build and as a fresh
install. The owner pass must cover the complete first-goal, returning-goal,
Workshop acceptance, difficult-day recovery, repeatable mastery, scroll/sound,
largest-text, VoiceOver, Reduced Motion, Ring/Silent, native handoff, relaunch,
and warm-performance journeys.

The two-identity pass must prove private and listed states, Discover opt-in and
opt-out, one-way Circle, reciprocal Mutuals, per-card audiences, offline Circle
retry without card loss, confirmed removal, report, block, code rotation, and a
positive signed App Attest exchange. `owner_device_accepted` stays open until
that exact Build 36 artifact looks good, feels good, and behaves cohesively on
the phone.

Only after those passes should the App Store draft receive the Build 36
screenshots and copy, select the Build 36 binary, and enter another public review
request. Codemagic's `release-evidence.txt` beside the IPA remains the authority
for the signed artifact; this document establishes the local pre-upload gate.
